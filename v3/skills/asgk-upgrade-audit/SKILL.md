# Material upgrade assessment

Assess the actual target baseline and candidate source changes under target-owned
read-only scope. Uncertain baseline remains uncertain. A new source version is not
a migration mandate. The human selects the evaluator; ASGK does not route models.

Compare responsibility and behavior, not source-tree shape: current GitHub issue/PR
authority, decisions and closeouts, context boundaries, roles, validation and recovery.
Preserve target adaptations and useful history. The candidate packet/Skill set must
not replace issue authority or become a mandatory install bundle.

Use source/target evidence, alternatives, risk, compatibility and rollback to recommend
minimum change or retain_current_state. Mechanical target claims are observations;
frontier judgment decides fit/depth. No module menu, automatic synchronization or extra
human gate merely because judgment is needed.

Write assessment_complete or blocked in the target's existing durable record with
rationale, evidence/limits, confidence/unknowns and exact next action. Any recommended
implementation follows the target's issue fields, allowed paths and applicable gates.
Do not copy CURRENT_STATUS, map, secrets, global Skills or migration ledgers from ASGK.
The user testing this candidate has not yet approved migration.
